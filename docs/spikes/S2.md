# S2 — pyslang 11 on a real SoC's RTL

**Question (IMPLEMENTATION_PLAN.md):** does pyslang 11 extract hierarchy, ports,
parameters, instances and clock/reset from a real project's RTL, including wrappers
generated by emacs verilog-mode (AUTO) and vendor IP?

Tried on 2026-09-28 with `pyslang==11.0.0` (Python 3.14, macOS arm64) on three blocks
of a training SoC, each a hand-written wrapper around unmodified open-source IP,
compiled through the block's own filelist:

| Block | Vendor IP under the wrapper | Errors | Elaborate time |
|---|---|---|---|
| PWM | PULP `apb_adv_timer`, OpenTitan `prim_clock_gating` | 0 | 0.01 s |
| UART | PULP `obi_uart`, `apb_to_obi`, `common_cells` | 0 | 0.01 s |
| CPU | lowRISC Ibex (`ibex_top`, full core), OpenTitan `prim` | 0 | 0.05 s |

## What works

- The API lives in submodules in 11.x: `from pyslang.driver import Driver,
  CommandLineOptions`, `from pyslang import ast` (`ast.SymbolKind`, `ast.VisitAction`).
  `Driver.parseCommandLine("slang -F <block>.f --top <top> ...")` reads a filelist.
- Full hierarchy from the wrapper down to the IP's leaves, with instance name,
  definition name and `file:line` of every instance.
- Ports with direction and resolved type (`logic[11:0]`), parameters with their
  elaborated values (`32'd12`; a 296-bit struct parameter comes back as a number, so
  store values as strings).
- Emacs-generated wrappers parse like any other file: the AUTO comments are only
  comments.

## What needs care (input for M1-04)

- **Mixed timescales** are an error in slang (not in Verilator): pass
  `--timescale 1ns/1ps` by default, configurable in the profile.
- **Filelists are tool-specific.** One filelist contained a Verilator-only
  `--top-module`, which slang rejects; filelists also differ in how paths resolve
  (`-F`, relative to the filelist, versus `-f`, relative to the working directory).
  The extractor should read filelists itself (sources, `+incdir+`, `+define+`),
  skip options it does not know with a warning, and take the path style from the
  profile.
- **Clock and reset by a loose name match are noisy:** `rst` matched
  `o_bus_axi_ar_burst`, and `clk` matched clock-enable outputs. Use the profile's
  anchored naming rules (for example `^i_clk_`, `^i_rst_n_`) on the top ports, then
  follow connections down the hierarchy.
- `--ignore-unknown-modules` keeps partial designs usable (a block whose IP is not
  vendored yet).
- FSM extraction was not tried.

## Recommendation

Use pyslang 11 for M1-04. Pin `pyslang>=11,<12`; build the compilation from our
own filelist reader rather than passing filelists straight to slang.

## Update 2026-09-29: pyslang 12

chipgraph now pins `pyslang>=12,<13` (12.0.0, released 2026-09-29).

- The 12.x stubs parse under mypy. The 11.x stubs did not (a parameter named `with` in
  `syntax.pyi`), which is why the extractor and the `naming` check imported pyslang
  through `importlib` as an untyped module. Both now use plain imports
  (`from pyslang import ast`, `from pyslang.driver import ...`,
  `from pyslang.syntax import ...`) and mypy checks the calls.
- The submodule layout and the APIs chipgraph uses are unchanged: the full suite, the
  tinysoc e2e, and the `naming` comparison on the QSoC corpus give the same results as
  on 11.0.0.
- 12.x adds one runtime dependency, `nanobind-backend` (the nanobind split-mode
  runtime, from the nanobind author).
