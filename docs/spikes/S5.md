# S5 — MCP Python SDK 2.x: server stdio, and Claude Code calling its tools

**Question (IMPLEMENTATION_PLAN.md):** does the MCP Python SDK 2.x let us run a stdio
server, and can Claude Code (or any MCP client) call its tools?

## What works

- `mcp` 2.2.0 (locked, `mcp>=2.2,<3`). 1.x `FastMCP` is gone; `mcp.server.fastmcp`
  raises `ModuleNotFoundError` pointing at `mcp.server.mcpserver.MCPServer`, the 2.x
  successor. `chipgraph.mcp.server.build_server` uses `MCPServer`: `@server.tool()`
  registers a typed async function (name/description/JSON Schema auto-derived);
  `server.run_stdio_async()` runs the stdio transport.
- Errors: a tool raising `mcp.server.mcpserver.exceptions.ToolError` (chipgraph wraps
  `AppError`/`ConfigError`/`GateError`) comes back as `CallToolResult(is_error=True)`
  with the message as text, never a crashed server loop.
- Testing: `mcp.Client(server)` connects to an `MCPServer` in-process
  (`InMemoryTransport`, no real transport) — used for 10 of 11 tests (list tools,
  `config_show`, `check` pass/fail, `build`→`status`, `approve`). One subprocess test
  starts the real `chipgraph mcp -C <tmp>` and talks to it with
  `mcp.Client(StdioServerParameters(...))`; it skips (not fails) if the handshake +
  one tool call don't finish within 10s.

## Usage in Claude Code

```
claude mcp add chipgraph -- uvx chipgraph mcp
```

or `.mcp.json`:

```json
{"mcpServers": {"chipgraph": {"command": "uvx", "args": ["chipgraph", "mcp"]}}}
```

Local checkout instead of a published package:

```json
{"mcpServers": {"chipgraph": {"command": "uv",
  "args": ["run", "--project", "/path/to/chipgraph", "chipgraph", "mcp"]}}}
```

`-C/--dir` and `--profile` are global options, before the subcommand:
`chipgraph -C /path/to/project mcp`.

## Verified in a real Claude Code session (2026-09-28)

Claude Code 2.1.283, headless, on a clone of a real project (19 blocks, `make` checks):

```bash
claude -p "Use the chipgraph MCP tool 'check' with blocks ['pwm'] ..." \
  --mcp-config mcp.json --strict-mcp-config \
  --allowedTools "mcp__chipgraph__check mcp__chipgraph__status"
```

with `mcp.json` running `uv run --project <chipgraph> chipgraph -C <project> mcp`.
Claude called `mcp__chipgraph__check` and `mcp__chipgraph__status`; the check results
(lint and naming, pass) matched `chipgraph check` on the same tree.

## Not verified here

Installing through the plugin (`/plugin install`), which needs `chipgraph` on PyPI
first (M0-19). Out of scope: `streamable-http`/`sse` transports (D35 only asks for
stdio) and auth.

## Recommendation

Ship `mcp>=2.2,<3` with `MCPServer` + stdio, as implemented. No blockers for M0-14 or
for M1-11's `next_task`/`get_context`/`submit` tools to reuse `build_server`'s pattern.
