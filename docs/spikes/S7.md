# S7 — Runtime `claude-code`: the task loop, role subagents, a write guard, tokens

**Question (IMPLEMENTATION_PLAN.md):** can the user's own Claude Code drive chipgraph's
loop `next_task` → a role subagent → `submit`, with the subagent limited in tools and
model, a `PreToolUse` hook refusing writes outside the task's `outputs`, several
subagents in parallel, and token use readable afterwards? It gates M1-11 (D35).

**Status:** run on 2026-09-30 in the lead's Claude Code 2.1.285, headless, Haiku 4.5 for
the main session and the subagent. Everything on the list works, except one point left
for a run after the Sonnet reset (2026-10-03 20:00): a subagent model **different** from
the main one.

## Harness (`docs/spikes/s7/`)

| File | Role |
|---|---|
| `s7_server.py` | Throwaway MCP server (`MCPServer`, stdio): `next_task` (hands out two tasks at once), `get_context` (spec + `outputs`), `submit` (every changed file must be an output of a dispatched task; outputs must exist; Verilator lint). Writes `.s7/allowed.json` for the hook |
| `hook_guard.py` | `PreToolUse` command hook on every tool (matcher `*`, so the log shows each agent's tool calls); for `Write|Edit|MultiEdit|NotebookEdit` it denies (`permissionDecision: deny`) any path not in `.s7/allowed.json`, and denies on any error (fail closed); logs every decision with `agent_id`/`agent_type` to `.s7/hook.log` |
| `setup.sh` | Copies tinysoc to `OUT` (must be `/tmp/s7-*`), writes the `rtl-author` subagent (tools `Read, Write, Edit, Glob, Grep, get_context`; no Bash; `model: $SUB_MODEL`) and the hook in `.claude/settings.json`, **then** commits, and writes `mcp.json` |
| `run.sh` | `setup.sh`, then one `claude -p` with `--max-turns`, `--strict-mcp-config`, `--output-format stream-json`; OpenTelemetry off |
| `report.py` | Summarises a run: tool calls, `Agent` calls, hook allow/deny, tools per `agent_id`, subagent Bash calls (stream and hook log), submit results, turns, duration, `total_cost_usd`, `usage`, `modelUsage` |
| `selftest.py` | Plays the agents' part (no model): tasks, context, hook allow/deny/outside-the-project, submit accept/reject |

Task `t2` asks, on purpose, for a README line outside its `outputs`: the hook must
refuse it and `submit` must still accept the task once only `rtl/tiny_sat.sv` changed.

## Verified without a model

- `selftest.py` builds the tree with `setup.sh` (the same script `run.sh` uses), starts
  the server from the generated `mcp.json` over stdio, and runs the hook as a
  subprocess: the committed tree is clean (`.claude/` is in the first commit); the hook
  allows an output, denies `README.md` and a path outside the project, ignores `Read`,
  and **denies on bad input or a broken `allowed.json`** (fail closed); submit accepts a
  lint-clean output even with `.claude/settings.local.json` present, and rejects a change
  outside the outputs and a missing output.
- The hook as a real subprocess, JSON on stdin, prints the documented deny object and
  logs `agent_type`.
- Hook input/decision format checked against the Claude Code hooks reference: file
  tools get an absolute `tool_input.file_path`; hooks from settings files run inside
  subagents too, with `agent_id`/`agent_type`; `-p` sessions treat the folder as trusted,
  so the project's `.claude/settings.json` hook runs. Subagent **frontmatter** hooks do
  not run in `-p` (workspace trust), which is why the guard lives in settings.

Notes from the runs:

- Haiku ignored the task's deliberate README instruction in both runs, so the deny path
  was exercised by a separate probe (same hook, same agent definition).
- `num_turns` (4) counts main-session turns only; the subagents made ~10 tool calls
  between them. So `--max-turns` does not bound subagent work: M1-11 needs its own
  budget (the engine's) per task.
- The hook receives `agent_id` and `agent_type`, so M1-11 can scope `allowed` per task
  and per subagent instead of the union used here.
- OpenTelemetry is not needed for tokens and cost; it stays off in `run.sh` because its
  console exporter would share stdout with the stream.

## Open questions for M1-11

- The guard reads `allowed.json` written by the server: in M1-11 the engine owns this,
  per task and per subagent (`agent_id` is in the hook input), not the union of
  dispatched tasks.
- Bash is simply not given to the role; a Bash write guard would need command parsing.
- `--max-turns` bounds only the main session; the engine must budget subagent work.
- The guard fails closed (any error denies), since Claude Code lets a call through when a
  hook exits with a code other than 0 or 2.

## Recommendation

Build M1-11 on this shape: MCP tools `next_task`/`get_context`/`submit`, one subagent
definition per role (frontmatter `tools` and `model`), the write guard as a
`PreToolUse` hook in the plugin's `hooks/hooks.json` (not in agent frontmatter, which
does not run under `-p`), and cost from the `result` event. Confirm the subagent model
with the Sonnet run before M1-11 relies on per-role models.
